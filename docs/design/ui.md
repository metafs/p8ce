# p8ce — UI の基本 / Interface

**Status:** Active
**Version:** 0.3
**Last Updated:** 2026-09-29

---

## Purpose

この文書は、画面の見た目・言葉・部品の正本である。トークンと部品の実装は `src/app/globals.css` と `src/ui/`、書体と部品構成の決定理由は ADR-0022 に置く。名称・ロゴの規則は `docs/brand/identity.md` に従う。

エージェントは、ここに書かれていない見た目の方針（色の追加、新しい装飾、別の書体）を一般論で補わない。必要なら Open items に質問として追加する。

## 判断の軸

| 軸 | 根拠 | 画面での意味 |
| --- | --- | --- |
| 比べない | ADR-0017、listing-policy | どの Event も同じ文法・同じ大きさで並べる。おすすめ、順位、大きさによる強調をしない |
| それぞれのペース | タグライン | 急かさない。残り時間の強調や煽りの語を使わない。過去の上演も今の上演と同じ重さで読める |
| 構造でつなぐ | G-002、scope §5 | 画面上の Artist・Venue の名前には必ず行き先（リンク）がある |
| 無彩色・editorial | DEC-UI-001（2026-09-19 決定） | 色で階層を作らず、文字組み・罫線・余白で作る |
| 残すものと消すもの | ADR-0018 | 中止は記録として残し、警告の見た目にしない。取り下げは跡を残さない |

## 色

公式色は `#141414` と `#ffffff` のみ（identity.md）。UI はその間のグレーだけを使い、アクセント色を持たない。

| トークン | 値 | 用途 |
| --- | --- | --- |
| `--ink` | `#141414` | 本文、罫線（強）、塗りのボタン |
| `--ink-2` | `#5f5f5b` | 補足の文字（白地で 6.4:1） |
| `--ink-3` | `#6e6e69` | 日付の曜日、注記、プレースホルダ、カレンダーの範囲外の日（白地で 5.1:1、`--ground` 地で 4.7:1） |
| `--ink-disabled` | `#9a9a95` | 無効化した操作のみ。文字には使わない（白地で 2.8:1 と、WCAG の 4.5:1 に届かない） |
| `--paper` | `#ffffff` | 公開面の地、パネル |
| `--ground` | `#f6f6f4` | 主催者・運営の地 |
| `--line` | `#e2e2de` | 行の区切り |
| `--line-field` | `#8e8e89` | 入力欄の枠（白地で 3.3:1、`--ground` 地で 3.0:1） |
| `--line-soft` | `#c8c8c3` | リンクの下線、控えめなボタン・ラベル・告知の枠。飾りであり、部品を見分ける手がかりには使わない |

文字は地に対して 4.5:1 以上のコントラストを保つ（WCAG 2.1 AA）。プレースホルダとカレンダーの範囲外の日も文字として扱う（2026-09-24、DH-13）。

空の入力欄は枠でしか見分けられないため、入力欄の枠は地に対して 3:1 以上を保つ（WCAG 1.4.11、2026-09-25、DEC-R10）。`--line-field` は入力欄だけに使い、下線や飾りの枠は `--line-soft` を使う。

運営画面のヘッダーだけは反転（`#141414` 地に白）とし、公開内容を変える操作の場であることを示す。

### 状態は形で示す

| 状態 | 表し方 |
| --- | --- |
| 中止 | 枠線のラベル「中止」。本文の告知は上罫線の帯。赤や塗りを使わない |
| 終了 | 淡い枠線のラベル「終了」 |
| 差し戻し | 塗りのラベル |
| 審査中・審査待ち | 破線のラベル |
| 下書き | 淡い枠線のラベル |
| 公開中 / 未公開 | 表の列では ● / ○ の印 |

## 文字

- 欧文と数字は Instrument Sans（400・500・600）。ロゴタイプと同じ書体で、`next/font/local` でリポジトリから配信する（ADR-0022）。
- 和文は端末の日本語フォント（ヒラギノ角ゴ、游ゴシック、Noto Sans JP など）に任せる。Web フォントは持たない（ADR-0012 の判断を維持）。
- 基準は本文 15px・行送り 1.8。Event の説明文は 16px・1.95。
- ページの h1 は 28〜44px・600。これより大きくしない。
- 日付と時刻は等幅数字（`tabular-nums`）で揃える。

### 日時の書き方

| 場面 | 形 | 例 |
| --- | --- | --- |
| 一覧の日付 | 月は詰め、日は2桁 | `9.25`、`10.03` |
| 曜日 | 一覧は「金曜日」、表の中は「金」 | |
| 時刻 | 24時間 | `19:30` |
| 年をまたぐとき | 年を添える | `2025年 · 土曜日` |
| 記録の日付 | 点区切り | `2026.09.19` |

「日本時間」の断りは、行ごとではなくページか節に一度だけ置く。

## レイアウト

- 公開面は左右 160px（1440px 幅で本文 1120px）。主催者・運営は左右 120px（本文 1200px）。狭い画面では 20px まで縮む（`--gutter`、`--gutter-app`）。
- 一覧はカードの格子にせず、日付でまとめた行のリストにする。1 Event は一覧に 1 回だけ現れ、次に来る日程の日に置く。
- カレンダーだけは開催日の表なので、1 Event を開催日ごとに置く。同じ日に複数の回があるときは 1 行にまとめ、時刻を縦に並べる。Festival そのものは置かず、子 Event の行に「フェスティバル」として名前を添える（REQ-DISCOVERY-001）。
- 区切りは罫線で行う。影、角丸、グラデーションは使わない。
- 表は狭い画面では枠の中で横にスクロールさせ、列を潰さない。
- 一覧の行は、時刻・種別・会場の列の幅が決まっている。行のリストが狭く、タイトルに約 100px 残らないときは、狭い画面と同じ並び（左に時刻、右に残りを縦に積む）に切り替える。画面幅ではなくリスト自身の幅で判断する（container query）。フィルターの横やノート PC の幅で、タイトルが潰れて会場と重なっていた（2026-09-25）。

## カレンダー

`/calendar` は「日ごと」を既定とし、`?view=month` で「月」を開く（`month` だけの古いリンクも「月」を開く）。

| 部分 | 決まり |
| --- | --- |
| 日付の帯 | 日曜はじまりの 4 週間。予定のある日だけがリンクで、選んだ日（`from`）から下に並ぶ。選んだ日は塗り、予定のない日は `--ink-3` の文字。狭い画面では日付だけが横にスクロールし、前後の週への移動は残す。スクロールする枠はキーボードで操作できる |
| 絞り込み | 地域・種別・会場・「無料のみ」。GET フォームで、URL に残る。「無料」はチケット料金がすべて `free` の Event |
| 行の詳細 | `<details>` で開く（JavaScript なし）。ほかの日程、参加方法、会場、上演ページとチケット・申込へのリンク。中止の Event には申込リンクを出さない |
| ページ送り | 20 行を目安に日の区切りで止め、「○○ 以降を表示」で次の日から始める |
| 月表示 | 1 日に 3 件まで。残りは「ほか N 件」で日ごとへ。日付を選ぶとその日からの日ごとを開く |

参考にした画面の構成は `docs/plans/calendar-day-view.md` にある。

## アクセシビリティ

目標は WCAG 2.2 AA。`tests/e2e/accessibility.spec.ts` が主要な画面を axe で検査し、違反があれば CI が落ちる（DH-13）。

- **フォーカス。** キーボードで移動したときは、すべての操作対象に `#141414` の 2px の枠を出す（反転ヘッダーでは白）。`outline: none` で消さない。
- **ページタイトル。** 各ページに固有のタイトルを付ける。形は「ページ名 | p8ce」。
- **ランドマーク。** 画面の内容はすべて header・nav・main・footer・名前付きの region のいずれかに入れる。
- **本文へスキップ。** どのページも、最初の Tab で「本文へスキップ」のリンクが左上に現れ、ヘッダーを飛ばして main へ移る（`src/ui/skip-link.tsx`、2026-09-25、DEC-R10）。普段は見えない。各ページの `<main>` は `mainContentId` を id に持つ。
- **横に長い表。** `src/ui/table-frame.tsx` で囲む。枠がフォーカスを受け取り、キーボードで横にスクロールできる。
- **フォームのエラー。** 項目のエラーは `aria-invalid` と `aria-describedby` で項目に結びつける。送信後にエラーが返ったら、最初のエラー項目へフォーカスを移す（`src/ui/use-focus-first-error.ts`）。
- **結果の通知。** エラーは `role="alert"`、操作の完了は `role="status"` で読み上げる（`Notice`）。
- **狭い画面。** 320px 幅で、表の枠の中を除き横スクロールを出さない（WCAG 1.4.10）。

## 部品

`src/ui/` はドメインを知らない部品を置く（code-structure.md）。表示用の値だけを受け取る。

| 部品 | 役割 |
| --- | --- |
| `Logotype` | 文字で組んだ `p8ce`。40px 未満の場面すべてで使う |
| `SiteHeader` / `SiteFooter` | 公開面の枠。現在地を `aria-current` で示す |
| `PageHead` / `AppPageHead` | ページの h1 と前置き。公開面と主催者・運営で2種類 |
| `Section` | 見出し付きの節。h2 は `<section>` の直接の子とし、節の名前になる |
| `StateLabel` / `Mark` | 状態の言葉と印（上表） |
| `Notice` | 操作結果とページ全体への告知。エラーは `role="alert"` |
| `DayGroups` / `DayGroup` | 日付を大きく置いて行をまとめる |
| `RowList` / `ListRow` | 一覧の1行（時刻・種別・タイトル・会場）。一覧、出演者、会場で列を揃える。`extra` は行の下（タイトルと会場の列）に置く内容で、カレンダーの「詳細」に使う |
| `DefinitionRows` | 項目名と値の表 |
| `TabNav` | Organization と運営の画面内の切り替え |
| `Segmented` | GET フォームで使う単一選択 |
| `EmptyState` | 空のときの一文 |

ドメインを知る部品は feature に置く。例: `features/discovery/components/event-row.tsx`（Event を `ListRow` に変換する）、`event-listing.tsx`（これから・日程未定・終了の3部構成）、`features/shared-entities/components/entity-event-sections.tsx`（出演者・会場の「これから / これまで」）。

## 言葉

公開面では、ドメインの語（`docs/product/glossary.md`）をそのまま見出しにしない。内部の値（enum）は画面に出さず、各 feature の `schema.ts` のラベル関数を通す。

| 内部 | 公開面 | 主催者・運営 |
| --- | --- | --- |
| Event 一覧 | 探す | Event |
| Artist | 出演者 | 出演者 |
| Venue | 会場 | 会場 |
| Artist / Venue Candidate | — | 出演者・会場の登録を申請、候補 |
| Ticket Offer | 参加方法（料金） | 料金 |
| Ticket / 申込 Link | チケット・申込 | チケット・申込先のURL |
| `draft` / `in_review` / `changes_requested` | — | 下書き / 審査中 / 差し戻し |
| `owner` / `admin` / `editor` | — | オーナー / 管理者 / 編集者 |
